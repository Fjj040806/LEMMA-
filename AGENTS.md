# LEMMA product and engineering principles

Treat LEMMA as a learning environment. The user's explicit product direction is that every future change must preserve the learner's willingness to continue by reducing effort and distraction.

- Keep problem selection/upload separate from the dedicated solving route (`#/solve/<localId>`). In solving mode, hide library navigation and dashboards. Keep the original problem visible and one current meaningful task prominent.
- Main tasks, hints and feedback must be comfortable to read: approximately 22–28px body, 26–32px task titles, generous line height (1.7–1.9), strong contrast, and roomy spacing. On narrow screens, core learning text should stay at least about 20–22px. Smaller metadata is secondary and must never carry essential guidance.
- Make the handwritten page the primary surface on tablets. Preserve ink before network operations. Avoid requiring screenshots, switching applications, or copying recognized text into another tool. Keep an editable recognition field in the same page.
- Retain typing as an equally usable input method. Without a configured recognition API, start offline examples in typing mode so learners are not blocked by a nonfunctional recognition path; handwriting remains available for saved notes.
- Offer one clear primary action. Keep help available without cluttering the primary writing flow. Preserve draft, original ink, submissions and assistance on errors, switching input method, pausing and resuming.
- Feedback must identify evidenced progress or a specific repair, not generic flattery or promises of grades. Show successful-step feedback before the next task, in large type. Keep unknown separate from wrong.
- No fabricated recognition, AI generation, math validation or learning outcomes. Model review is not a formal proof. No-key behavior must be explicit and usable.
- Protect independent-check integrity: recognition transcribes only, no live strategy/answer feedback; hints or solution viewing must change assistance status. Similar problems must start as new attempts with private answers retained on the server.
- Preserve seven-language access and original student text/formulas. Never translate or overwrite student evidence in place.
- Use meaningful checks for state, disclosure, uploads, ink, race conditions and persistence. Browser-check dedicated solve, resume and tablet/narrow layouts when tools are available. Report actual hardware and live-API verification limits candidly.
- Motion direction: restrained navy/cyan neural connections, pathfinding light and untangling threads. Reserve immersive motion for arrival and the problem library; solving stays quiet. Always offer pause/reduced motion, honor OS preference, skip arrival on direct solving routes, and avoid replaying it during the same browsing session.
